# SOP 格式規範

## 目的

每個 Skill 都必須包含一個 `## SOP` section，作為執行該 Skill 任務的流程骨幹。SOP 要讓執行者知道工作從哪裡開始、依什麼順序進行，以及如何判斷結果已完成。

本文件規範 SOP 的結構與步驟寫法；它不是特定 Skill 的執行流程。Skill 的任務知識、工具細節、範例與例外處理，應寫在 SOP 以外的適當段落，並由 SOP 步驟指向或使用。

## 必要結構

每個 Skill 的 SOP 必須符合以下結構：

1. 使用 `## SOP` 作為唯一的 SOP 區段標題。
2. 在 SOP 區段下，以 `### Phase N -- 階段目的` 劃分流程階段。`N` 從 1 開始，依序遞增，不跳號。
3. 每個階段使用從 `1.` 開始的 Markdown 編號清單列出步驟；步驟按該階段內的執行順序排列。
4. 階段與步驟的數量依 Skill 任務需要決定，不為了符合固定數量而拆分或合併工作。

## 步驟寫法

1. 每個步驟以一個清楚的行動動詞開頭，例如 `READ`、`THINK`、`WRITE`、`CHECK`、`REVIEW`、`ASK` 或 `DELEGATE`。動詞可依任務擴充，不限於此清單。
2. 每個步驟描述一項可執行的主要行動，並指出行動對象、所需判準或預期產出；避免只寫抽象口號，例如「處理資料」或「確保品質」。
3. 將必要的輸入、決策條件與完成判準寫清楚。若某條件會改變後續流程，明確寫出條件及對應的下一步。
4. 按實際執行順序安排步驟。需要讀取或確認的資訊應先於依賴該資訊的決策或產出。
5. SOP 應涵蓋從觸發任務到交付或確認結果的主要路徑；不要求列出與任務無關的通用工作習慣。

## 範本

```markdown
## SOP

### Phase 1 -- <階段目的>

1. READ <讀取的輸入或脈絡>，確認 <需要掌握的資訊>。
2. THINK 根據 <判準> 決定 <需要做的選擇>；若 <條件>，則 <後續行動>。
